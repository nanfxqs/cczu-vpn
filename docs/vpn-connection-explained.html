CCZU VPN Proto
Linux 连接实现图解

此项目使用 TUN 虚拟网卡承接内核 IP 包，以自定义二进制帧封装后，经由连接到 zmvpn.cczu.edu.cn:443 的 TLS 加密 TCP 连接发送。它不是 WireGuard、OpenVPN 或 IPsec。

运行时数据流

1. SSO 登录
用户名、密码 → cczuni
→
2. 服务配置
获取 token、虚拟 IP、网关、DNS、校内网段
→
3. TLS 连接
TCP 443 + Rustls
→
4. 隧道鉴权
发送用户名 + token
→
5. Linux 网络配置
创建 TUN、路由、DNS
→
6. IP 包双向转发
TUN ↔ TLS 帧，约 5 秒心跳

加密协议：TLS 1.3

应用：SSO 请求、自定义鉴权帧和 IP 数据帧
TLS：Rustls / Tokio-Rustls 加密、认证、完整性保护
TCP：到服务端 443 端口的可靠字节流
IP / Wi-Fi：本机默认网络出口

本机对服务端实际探测：TLS 1.3、TLS_AES_256_GCM_SHA384、X25519 临时密钥交换，证书 *.cczu.edu.cn 验证通过。

AES-256-GCM 提供数据加密和认证；X25519 提供前向保密。实际协商套件可能随服务端变化。

TLS 证书验证默认开启

CLI 默认使用 Mozilla 根证书集合验证服务器证书、域名和 TLS 签名。

已修复：StartOptions::default().no_verification 从 true 改为 false。

注意：库 API 仍保留显式 no_verification: true 的危险兼容选项；CLI 不提供关闭验证的参数。

源码：src/types.rs、src/vpn/tls.rs

隧道帧：封装，不是第二层加密

Linux 内核 IP 包
  ↓ TUN: CCZU-VPN-PROTO
[version=1][kind=4][length: u16 big-endian][xid: 4 bytes][app_id=1][原始 IP 包]
  ↓ TLS record（由 TLS 负责加密与完整性）
TCP → zmvpn.cczu.edu.cn:443

kind=4 是数据帧，kind=2 是控制帧。自定义帧没有自己的加密或 MAC，它的安全性完全依赖外层 TLS。

源码：src/vpn/protocol/write.rs、read.rs、stream.rs

TUN

Linux 三层虚拟网卡。程序从中读取原始 IP 包、向其中写回入站 IP 包；内核把它当作网络接口。它不加密，也不同于处理以太网帧的 TAP。

Split tunnel

只让服务端下发的校内 IPv4 网段走 VPN，其他公网流量仍走默认路由。

Token

SSO 成功后取得的临时授权凭据。隧道鉴权帧发送用户名与 token，而不是重复发送密码。

Linux CLI：本次补齐的三个功能

功能实现退出或失败处理
TLS 安全默认值默认验证证书仅库调用者显式开启才跳过验证
IPv4 分流路由ip route + 一条优先级 8000 的 ip rule，使 main 表非默认路由优先于 Clash TUN启动时清残留；失败时回滚；退出时倒序删除
接口 DNSresolvectl dns + resolvectl domain ~cczu.edu.cn失败时回滚；退出时 resolvectl revert

源码：src/cli.rs；仅在 target_os = "linux" 编译。

Linux 运行权限

CLI 会启动外部 ip 与 resolvectl 命令。仅给主程序授予 CAP_NET_ADMIN 不会自动把该能力传给这些命令，DNS 配置也可能需要 polkit 授权。因此建议以 root 身份运行：

cargo build --release --locked
sudo ./target/release/cczu-vpn-proto

与 Clash Verge 共存时可以保留 TUN 和系统代理，但应在规则增强的 prepend 中把 zmvpn.cczu.edu.cn、211.65.64.100/32、cczu.edu.cn 和 172.16.0.0/12 设为 DIRECT。客户端会为学校地址及 VPN DNS 安装主路由和一条优先级 8000 的策略规则，使 Mihomo 的直连出站进入 CCZU VPN。
